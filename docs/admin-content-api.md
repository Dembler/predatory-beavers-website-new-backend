# Редактирование сайта

Перед запуском обновлённого API примените миграции:

```powershell
.venv/Scripts/python.exe -m alembic upgrade head
```

Миграция `0007` добавляет таблицу текстовых блоков, одну вводную запись истории и три
записи правил. Существующие игроки, команды, игры, фотографии и пользователи сохраняются.

## Текстовые блоки сайта

`GET /api/v1/content/{section}` доступен всем. Разделы: `history`, `rules`,
`contact_channels`, `captains`, `player_roles`, `viewing_tips`.
Ответ: `{"status":"success","message":"Content retrieved","data":{"items":[...]}}`.
Публичная выдача включает только опубликованные блоки в порядке `sort_order`.
Текст хранится как обычный текст, переносы строк сохраняются; HTML не выполняется.

Административные операции доступны ролям `EDITOR` и `ADMIN`:

| Метод | URL | Назначение |
|---|---|---|
| GET | `/api/v1/admin/content?section=history&page=1&page_size=50` | Список, включая черновики |
| GET | `/api/v1/admin/content/{id}` | Один блок |
| POST | `/api/v1/admin/content` | Создать блок |
| PATCH | `/api/v1/admin/content/{id}` | Изменить переданные поля |
| DELETE | `/api/v1/admin/content/{id}` | Удалить блок из выдачи |

Поля создания: `section` (один из перечисленных разделов), `title` (1–200 символов),
`body` (1–30000 символов), `sort_order` (целое ≥ 0, по умолчанию 0),
`active` (по умолчанию `true`). Порядок ограничен значением `2147483647`, чтобы
некорректный ввод не переполнил целочисленное поле SQLite. Пробельные заголовки и тексты отклоняются.
PATCH не принимает `null` для этих полей.

Дополнительные поля всех блоков: `subtitle` (до 200 символов), `link_url`
(абсолютный HTTP/HTTPS URL до 2048 символов), `link_label` (до 100 символов).
По умолчанию они равны `null`; явный `null` в PATCH очищает поле, а отсутствие
поля сохраняет его значение. Пробелы по краям обрезаются, пустые строки становятся
`null`. URL проверяется как `HttpUrl`, хранится и передаётся строкой. Эти поля также
входят в публичную выдачу и аудит изменений. Прежние запросы истории и правил
продолжают работать без передачи дополнительных полей.

Миграция `0009` расширяет допустимые разделы и добавляет три nullable-колонки.
Она сохраняет все прежние значения и не добавляет контент. Откат на `0008`
разрешён только при отсутствии строк новых разделов и заполненных дополнительных
полей, включая скрытые и удалённые записи. Иначе downgrade явно завершается
ошибкой до изменения схемы, чтобы не удалять данные. Перед откатом такой контент
нужно отдельно экспортировать и перенести; автоматического удаления нет.

## Фотографии

`GET /api/v1/admin/media` возвращает страницу фотографий, начиная с новых.
Загрузка — `POST /api/v1/admin/media`, multipart-поля `file` и необязательный `alt_text`.
Допустимы статические JPEG, PNG и WebP, по умолчанию до 8 МиБ на файл.
Проверяется содержимое изображения, а не расширение имени или заявленный MIME-тип.
Авторизация выполняется до разбора multipart. Входящий поток ограничен размером файла
плюс 64 КиБ для заголовков; допускается один файл и одно текстовое поле.
Изображения нормализуются в WebP; прозрачность PNG сохраняется, а метаданные удаляются.
`PATCH /api/v1/admin/media/{id}` изменяет `alt_text`; `null` очищает описание.
`DELETE /api/v1/admin/media/{id}` скрывает неиспользуемую фотографию.

Используемую в игроке, команде, матче или достижении фотографию удалить нельзя:
API отвечает `409`, пока ссылка не будет снята. Это распространяется и на записи,
временно скрытые с сайта. Удаление самих записей снимает это ограничение.
Повторная загрузка такого же изображения переиспользует запись; удалённая фотография
восстанавливается. Физические файлы сохраняются для восстановления.

Все изменения защищены сессией и заголовком `X-CSRF-Token`, записываются в журнал аудита.
Токен можно получить после входа через `GET /api/v1/auth/csrf`.

## Изолированная проверка в браузере

```powershell
.venv/Scripts/python.exe scripts/setup_e2e.py --serve
```

Скрипт делает согласованную SQLite-копию `data/local.db` (либо исходного снимка, если рабочей базы ещё нет) только для чтения, копирует фотографии
в отдельный каталог и обновляет схему только копии. Создаёт тестового администратора
со случайным паролем в gitignored `data/e2e-credentials.json` и запускает API на
`http://127.0.0.1:8000`. Повторный запуск переиспользует тестовые данные. Исходная база,
фотографии и пароли пользователей не изменяются. Тестовые изменения остаются в `data/e2e.db`.

Перед изменяющими E2E-проверками запросите `/api/v1/health/e2e` через тот же адрес, что
использует интерфейс. Передайте `X-E2E-Runtime-Token` из поля `runtimeToken` файла credentials.
Сверьте `isolated`, `databasePath` и `mediaPath`. Без правильного токена, вне режима `test`
или с базой, имя которой отличается от `e2e.db`, endpoint отвечает 404.

## Обычный локальный запуск

```powershell
.venv/Scripts/python.exe scripts/setup_local.py
.venv/Scripts/python.exe scripts/setup_local.py --apply --serve
```

Первая команда только читает схему и счётчики. При первом запуске с `--apply` создаётся
рабочая `data/local.db` из исходного снимка `data/predatory_beavers.db`. Вторая команда
создаёт согласованную SQLite-копию `data/local.before-admin-*.db`, обновляет рабочую базу и запускает API
на `127.0.0.1:8000`. Если активного администратора ещё нет, создаёт его со случайным
паролем в `data/local-admin-credentials.json`. Существующие пароли сохраняются.
Рабочая база, оба credentials-файла, тестовые базы, копии фотографий и резервные копии исключены из Git.
Исходный отслеживаемый снимок не изменяется и не получает локального администратора.

Миграция `0007` допускает откат на `0006`: остальные таблицы сохраняются, таблица
истории и правил удаляется вместе с её содержимым. Для сохранения отредактированных
текстов используйте резервную копию; downgrade не является способом восстановить текст.
Откат и повторное применение проверяются только на отдельных тестовых базах.
