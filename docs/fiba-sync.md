# FIBA 3×3: проверяемые регистрации

`scripts.collect_fiba_games.collect_watched(watchlist_path, api_key=None, client=None)`
читает `docs/fiba-watchlist.json` и возвращает JSON-совместимый отчёт: `status`,
`results`, `coverage`, `registrations`, `errors`. Строки `results` проверены моделью
`PublicResult` и подходят общему импортеру `import_public_results.apply_import`.
Сам сборщик не меняет ни базу, ни манифесты.

В серверном окружении нужен разрешённый FIBA ключ `APP_FIBA_API_KEY`. Ключ
передаётся только в заголовке `X-Application-Key` на фиксированный адрес
`https://api.fiba3x3.com/api`. Ключ не кладут в watchlist, URL, клиентский код или
отчёт. Без ключа сборщик возвращает `auth_required` без сетевых запросов. Ответы
401/403 также дают `auth_required`; обходов ограничения нет.

FIBA официально прекратила Premium API. Для доступа к данным соревнований и
игроков служба FIBA просит описать проект по адресу `3x3digital@fiba.basketball`:
[актуальная официальная инструкция](https://help.fiba3x3.com/en/support/solutions/articles/35000118581-what-is-fiba-3x3-premium-api-).
Схемы взяты из [официальной документации API](https://api.fiba3x3.com/swagger/docs/v1).
15 ноября 2026 года документация отвечала 200, а запрос известной регистрации
без ключа — 403. Положительная проверка настоящих ответов потребует выданного
для проекта ключа; тесты адаптера используют документированные поля и mock-ответы.

## Что именно отслеживается

Watchlist содержит одну ранее проверенную мужскую регистрацию в московском
финале «Оранжевого атома» 5–6 декабря 2025 года. Это ограниченная подписка на
конкретную регистрацию, а не на все будущие соревнования клуба. Новую мужскую
или женскую регистрацию добавляют после проверки официальной ссылки. Сборщик
не угадывает пол по названию, не относит к клубу игры всех одноимённых команд и
не выводит женскую регистрацию из мужской.

`TeamInEventId` из ссылки разрешается через `TeamRegistrationPublic` в `TeamId`
и `DivisionId`. `DivisionTeamsCore` даёт имена соперников, а `DivisionGames` —
игры дивизиона. `category_id` и `DivisionId` различаются. Документированная
регистрация не гарантирует `EventId`, поэтому известный `event_id` задан отдельно
и сверяется, если источник его вернёт. `team` и `season` берутся из проверенной
конфигурации; игра отбирается только по точному `TeamId`.

В базе игры имеют `source=fiba3x3`, `external_id=GameId`. Завершёнными становятся
только `Official`/`OfficialForfeit` с двумя целыми неотрицательными очками и
победителем, согласованным со счётом. Равный, неполный или противоречивый счёт
отклоняет всю регистрацию. `Scheduled` всегда получает пустые очки. Остальные
видимые неподтверждённые статусы получают `unpublished`; скрытые/удалённые игры
не публикуются. Точная дата берётся только из опубликованной даты игры, включая
вариант полей `DateRangeModel` из Swagger. Сохраняется календарный день в
опубликованном смещении времени. Дата турнира, текущий день и выдуманное время
начала не подставляются вместо отсутствующей даты игры.

## Правила для автоматического запуска

Оркестратор объединяет только регистрации с `status=ok`. Для неуспешной
регистрации `results` не содержит даже тех строк, которые успели пройти проверку
до ошибки. Прежние записи в базе и сохранённом манифесте нужно оставить.
Сборщик ничего не удаляет; отсутствие игры в текущем ответе не является командой
удалить её из истории. Пустой успешный ответ сообщает только о текущем состоянии
конкретной регистрации и не доказывает отсутствие матчей клуба в других турнирах.
Фоновый запуск сохраняет список проверенных идентификаторов каждой регистрации.
Если из следующего ответа исчезла опубликованная игра (в том числе скрытая или
удалённая источником), импорт этой проверки отклоняется с сохранением прежних данных.
Покрытие архива обновляется только для успешно проверенных регистраций;
его число записей учитывает сохранённые игры, а не только строки последнего ответа.

`registrations[].external_ids` перечисляет успешно проверенные `GameId` текущего
запроса. `coverage.records` — число строк, полученных этим запуском, не число
ранее сохранённых матчей. Покрытие успешной подписки всё равно имеет статус
`partial`, поскольку будущие регистрации автоматически не обнаруживаются.

Для ручной диагностики без записи: `python -m scripts.collect_fiba_games`.
