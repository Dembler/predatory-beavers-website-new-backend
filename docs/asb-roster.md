# Проверенный состав АСБ

Проверено 4 ноября 2026 года. Для сезона **2026/27 подтверждены 15 мужчин и
15 женщин** в действующих заявках ВГУ. Каждый игрок имеет `accessStatus=Access`,
`leaveTeam=false`, `personType=Player` и публичную фотографию АСБ.

Новый официальный сайт использует публичный сервис `asb.sportoteka.org`.
Старый виджет `asb.infobasket.su/Widget/TeamRoster` возвращает пустой текущий состав,
поэтому его отсутствие не было принято за отсутствие заявки. Ключевым оказался
правильный тег текущего регионального соревнования:

- [Мужская команда](https://asbasket.ru/team/7433?season=2027&league=asb-cfo-36-m),
  ID 7433, соревнование 1415975, тег `asb-cfo-36-m`.
- [Женская команда](https://asbasket.ru/team/7695?season=2027&league=asb-cfo-36-w),
  ID 7695, соревнование 1415977, тег `asb-cfo-36-w`.

Сборщик сначала запрашивает `abc/teams/comps?teamId=…&season=2027`, затем
`abc/teams/info?id=…&season=2027&tag=…`. Для публикации обязательны совпадение
команды, `selectedSeason`, `selectedTag`, актуального соревнования и его сезона.
Состав берётся из `abc/teams/roster`, статистика — `abc/teams/stats` с теми же
командой, сезоном и тегом. Ссылки API сохранены в `asb-roster.json` и в БД.

**Статистика текущего сезона пока не опубликована:** оба `stats` возвращают
`players=[]`, `games=0`, `totalStats=null`. Для **игроков подтверждённого текущего
состава** по внешнему ID выбраны их последние опубликованные показатели за ВГУ.
Сезон состава остаётся `2026-2027`, а сезон статистики каждого игрока указан
отдельно в `statistics_season`; его точный источник — `statistics_source_url`.

На 4 ноября 2026 года хотя бы один показатель найден для 20 из 30 игроков:

| Команда | Состав 2026/27 | Итоги 2025/26 | Итоги 2024/25 | Нет опубликованных показателей |
| --- | ---: | ---: | ---: | ---: |
| Мужчины | 15 | 10 | 1 | 4 |
| Женщины | 15 | 8 | 1 | 6 |

У двух из этих 20 игроков опубликованы только минуты; отсутствующие очки,
передачи и подборы остаются `null`. Игроки без подходящих итогов также остаются
в текущем составе, со всеми статистическими полями `null`.

Порядок выбора: пригодная статистика текущего сезона, затем более ранние сезоны
по убыванию. Пригодная строка имеет реальные выходы на площадку (`games > 0`)
и хотя бы один опубликованный показатель, включая настоящий ноль. Все суммы,
число игр и источник выбираются **одним комплектом**. Даже если новый комплект
не содержит передач или подборов, они не дополняются из более старого сезона.

Исторические корневые соревнования проверяются по официальным индексам
[мужской](https://asb.infobasket.su/Widget/GetTeamSeasons/7433) и
[женской](https://asb.infobasket.su/Widget/GetTeamSeasons/7695) команды.
Проверяются совпадение `Year` и `SeasonName`, уникальность сезона, `CompID`
из этого индекса и точное совпадение `TeamID` в ответе статистики. Индексы
покрывают 2018/19–2025/26 у мужчин и 2019/20–2025/26 у женщин; для игроков
без показателей проверены все эти доступные сезоны.

Для прошлых лет используется общий итог команды за сезон, например
[мужчины 2025/26](https://asb.infobasket.su/Widget/TeamStats/7433?compId=49695&format=json),
[женщины 2025/26](https://asb.infobasket.su/Widget/TeamStats/7695?compId=49695&format=json),
[мужчины 2024/25](https://asb.infobasket.su/Widget/TeamStats/7433?compId=48154&format=json),
[женщины 2024/25](https://asb.infobasket.su/Widget/TeamStats/7695?compId=48154&format=json).
Это важно: современный индекс мужчин за 2025/26 содержит региональную лигу и
Лигу Белова, поэтому региональная таблица не является полным итогом сезона.
Корневой источник охватывает соревнования сезона без сложения пересекающихся
агрегатов. Число реальных выходов берётся из `InGameCount`, а не `GameCount`,
включающего попадания в заявку без выхода. Готовые `Avg*` не используются.

Сохраняется только явный список разрешённых полей: внешний ID игрока, ФИО,
фотография, число сыгранных матчей, суммы очков/передач/подборов/секунд,
сезон статистики и официальный URL. Из исторических ответов сохраняются
только показатели совпавших ID текущей команды, без старых ФИО и фотографий.
Даты рождения, возраст, гражданство, контакты и остальные поля исходного ответа
не сохраняются в файлы или БД. Ответы целиком не кешируются.

Среднее вычисляется из сумм конкретной команды и сезона: `total / games`,
минуты — `seconds / games / 60`. Нулевые опубликованные суммы остаются нулями;
отсутствующие показатели и показатели при нулевом числе игр остаются `null`.
Средние разных турниров не усредняются. Если у команды появится больше одного
текущего соревнования, синхронизация остановится до проверки пересечений игр.

Миграция `0011` добавляет отдельные таблицы `asb_roster_snapshots` и
`asb_roster_members`; `0012` добавляет сезон и источник показателей каждого
игрока. DDL `0011` зафиксирован и не зависит от будущих изменений ORM, поэтому
новая установка и обновление существующей БД проходят одинаково.
Исходная таблица `players` и ручные редакторские карточки
сохраняются. Исключённые из заявки игроки отмечаются `is_listed=false`, без удаления.
Исторические заявки не выдаются за текущие; в новом сезоне API возвращает пустой
состав, пока не появится подтверждённая заявка. По умолчанию API выбирает только
текущий сезон. Явный служебный выбор `latest_published` всегда указывает реальный
сезон и `is_current_season=false`, если он уже завершился.

```powershell
.\.venv\Scripts\python.exe scripts/sync_asb_roster.py          # офлайн-проверка
.\.venv\Scripts\python.exe scripts/sync_asb_roster.py --fetch  # обновить манифест
.\.venv\Scripts\python.exe scripts/sync_asb_roster.py --apply  # backup + миграция + импорт
.\.venv\Scripts\python.exe scripts/cache_asb_roster_photos.py         # проверить локальные фото
.\.venv\Scripts\python.exe scripts/cache_asb_roster_photos.py --fetch # скачать недостающие фото
```

`setup_local.py --apply` импортирует сохранённый манифест без сети. Перед каждым
применением создаётся согласованная резервная копия рабочей SQLite БД; исходная
`data/predatory_beavers.db` запрещена как цель. Идентичные повторные применения
не добавляют игроков и не изменяют их строки.

- `GET /api/v1/asb-roster/men` и `/women`: `ApiResponse.data` с контекстом сезона
  и `players`. Поля игрока: `id`, `external_player_id`, `full_name`, `photo_url`,
  `games_played`, `points_per_game`, `assists_per_game`, `rebounds_per_game`,
  `minutes_per_game`, `statistics_season`, `statistics_source_url`.
  Последние два поля — `string | null`; сезон записан как `2025-2026`,
  источник ведёт непосредственно к официальному JSON с выбранным итогом.
  Контекст `season` по-прежнему обозначает сезон состава, а контекстный
  `stats_source_url` — источник текущего сезона. Эти поля не подменяют
  индивидуальную атрибуцию исторических показателей.
- `GET /api/v1/asb-roster/{team}/players/{uuid}`: тот же контекст и `player`.
  Игрок другой команды или сезона не доступен через текущий состав.

Проверки: API списка и карточки, запрет чужого игрока, смена сезона без подстановки
старого состава, повторный импорт, сохранение исключённых строк, backup, отсутствие
личных полей, различие `null` и нулей, расчёт средних из сумм и свежая установка.

## Локальные фотографии

Все 30 официальных фотографий включены в пакет backend как
`modules/roster/assets/photos/*.webp` и входят в wheel через `package-data`.
Браузер получает изображения с нашего сервера: поле `photo_url` содержит
`/api/v1/asb-roster/{team}/players/{uuid}/photo`. Исходный URL остаётся в БД и
манифесте для проверки происхождения. Запрос фотографии не обращается к внешней сети.

Сборщик загружает только URL из проверенного манифеста, проверяет официальный хост,
размер и тип, применяет ориентацию EXIF и кодирует новый WebP из чистых пикселей.
EXIF, ICC и XMP не сохраняются. Имя файла связано с SHA-256 точного исходного URL;
индекс дополнительно содержит контрольную сумму WebP. Подмена URL или повреждение
файла не приводят к выдаче другого портрета. Произвольного URL-прокси нет.

Фотография выдаётся только участнику опубликованной текущей заявки нужной команды.
Несуществующие, исключённые и прошлогодние участники получают 404. Если для нового
официального URL ещё нет локального файла, `photo_url=null`, без внешнего запасного
запроса из браузера. Обновление: сначала `sync_asb_roster.py --fetch`, затем
`cache_asb_roster_photos.py --fetch`, проверка и `sync_asb_roster.py --apply`.
`--fetch` не загружает повторно неизменившиеся файлы; `--fetch --refresh` явно
перекодирует их заново. Обычный setup проверяет комплект фото без сети.
