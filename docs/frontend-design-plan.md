# «Хищные Бобры»: визуальная концепция и план фронтенда

Статус: план и исследование, без реализации интерфейса.

Дата исследования: 8 августа 2026 года.

## 1. Решение в одном абзаце

Публичный сайт предлагается собирать на готовом [Nuxt UI Landing template](https://ui.nuxt.com/templates), а будущую административную часть — на готовом Dashboard template из той же системы. До разработки макеты собираются в официальном [Nuxt UI Figma Kit](https://ui.nuxt.com/figma). Бренд сохраняет тёмно-синий фон старого сайта, белый, красный акцент, клубную эмблему и обязательные следы когтей. Рекомендуемое направление — гибрид «Game Night + Editorial»: первый экран работает как афиша ближайшего матча, а состав, результаты и история клуба подаются крупными редакционными блоками.

Мы не проектируем собственную библиотеку кнопок, форм, меню, таблиц и модальных окон. Собственными остаются только брендовый слой и доменные композиции: карточка матча, карточка игрока, таблица результатов и декоративные когти.

## 2. Границы первого этапа

В первый публичный релиз входят:

- главная страница;
- мужская и женская команды;
- игроки;
- расписание и результаты;
- турнирная таблица;
- клуб и достижения;
- правила;
- контакты и залы.

Пока не входят:

- регистрация, личный кабинет и отдельный дизайн авторизации;
- административная панель;
- Telegram-бот;
- магазин, билеты, новости и видеораздел без соответствующего контента/API;
- новый логотип или перерисовка фирменного знака.

Админку можно будет добавить позднее из готового Nuxt UI Dashboard template, не меняя публичную дизайн-систему.

## 3. Что сохраняем из старого бренда

Источник визуальных материалов — [старый репозиторий клуба](https://github.com/Dembler/Web_AppSite_Predatory_Beavers). Код и старую вёрстку не переносим.

| Legacy-материал | Решение | Использование |
|---|---|---|
| `fonbeavers.png` | сохранить как визуальную основу | тёмная фактурная подложка сайта после оптимизации |
| `kogti.png`, `kogtiniz.png` | обязательно сохранить | hero, переходы между секциями, заголовки внутренних страниц |
| `Рисунок1.png`, `Рисунок2_2.png`, `hat@3x.png` | использовать как референс | композиция hero и фирменная эмблема |
| `Match.png` | сохранить идею, оптимизировать | светлая текстура карточек матчей и таблиц |
| `foncard.png` | использовать только как референс | лёгкий рисунок когтей на светлых карточках |
| `cursor*.png` | не переносить | нестандартный курсор ухудшает привычное взаимодействие |
| изображения таблиц | не переносить как данные | таблицы строятся из API и остаются доступными/адаптивными |
| логотипы партнёров | после проверки прав и актуальности | отдельная спокойная секция партнёров |

До релиза следует запросить исходную эмблему клуба в SVG/PDF/AI. Растровый логотип из большого баннера нельзя считать достаточным master-файлом.

## 4. Основная палитра

Палитра извлечена из старого CSS, `fonbeavers.png`, клубного баннера и карточек. Она не меняет узнаваемость, но задаёт цветам строгие роли.

| Токен | Цвет | Роль |
|---|---:|---|
| `brand-navy-900` | `#042A4E` | основной фон, header, footer |
| `brand-navy-700` | `#1E325B` | поднятые тёмные поверхности, карточки |
| `brand-red-700` | `#CB1914` | основные CTA, активный пункт, важный счёт |
| `brand-red-500` | `#F81C0E` | только декоративное свечение и небольшие акценты |
| `brand-ice-100` | `#D8DDEA` | светлые панели, разделители, неактивные поверхности |
| `brand-white` | `#FFFFFF` | основной текст на тёмном фоне |
| `ink-navy` | `#042A4E` | текст на светлом фоне |

Проверенные сочетания:

| Текст / фон | Контраст | Решение |
|---|---:|---|
| белый / `#042A4E` | 14,52:1 | основной тёмный режим |
| белый / `#1E325B` | 12,63:1 | тёмные карточки |
| белый / `#CB1914` | 5,69:1 | доступная красная кнопка |
| белый / `#F81C0E` | 4,07:1 | не использовать для обычного текста |
| `#042A4E` / `#D8DDEA` | 10,68:1 | светлые таблицы и карточки |

Таким образом, яркий legacy-красный `#F81C0E` остаётся частью характера бренда, но для кнопок с белым текстом используется более тёмный `#CB1914`. Требование WCAG AA для обычного текста — не менее 4,5:1; основание — [WCAG 2.2, Contrast Minimum](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html).

Статусы победы, поражения, переноса и live-состояния не обозначаются одним цветом: цвет всегда сопровождается подписью или иконкой.

## 5. Система фонов

### Основной тёмный фон

- Базовый цвет — `#042A4E`.
- Поверх него — оптимизированная версия `fonbeavers.png` с мягкими диагональными мазками.
- Текст всегда находится на однотонной safe-подложке либо на участке с гарантированным контрастом.
- Фон не прокручивается отдельным тяжёлым fixed-слоем на мобильных устройствах.

### Светлый игровой фон

- Белый или `#D8DDEA` с почти незаметной текстурой `Match.png`.
- Используется для расписания, турнирной таблицы и длинного текста.
- Не более двух типов поверхностей на одном экране: тёмная и светлая.

### Фотографический фон

- Только одна сильная фотография в hero или editorial-секции.
- Обязателен однотонный navy-overlay под текстом.
- В первом релизе нет фонового видео: оно не нужно для узнаваемости и ухудшает LCP.

## 6. Когти — обязательный фирменный элемент

Когти являются частью дизайн-системы, а не случайной картинкой.

Обязательные появления:

1. крупный след в правом верхнем или нижнем углу hero;
2. один разрыв/переход между тёмной и светлой секциями главной;
3. компактный след в заголовке внутренних страниц;
4. едва заметный след на карточке игрока или матча при наведении/фокусе.

Правила:

- базовая форма — существующие `kogti.png`/`kogtiniz.png`, позже допускается аккуратная векторизация без изменения силуэта;
- белые когти — на navy, красные — только как небольшой акцент, navy — на светлой панели;
- когти никогда не проходят через основной текст, счёт, лицо игрока или интерактивный элемент;
- одновременно в viewport видна одна крупная группа когтей, иначе мотив превращается в визуальный шум;
- декоративный элемент получает `aria-hidden="true"` и не перехватывает клики;
- движение допускается только как короткое появление; при `prefers-reduced-motion` анимация отключается согласно [рекомендации MDN](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@media/prefers-reduced-motion).

Критерий приёмки: когти видны на главной и на каждом шаблоне внутренней страницы, но контент остаётся читаемым при ширине 390 px.

## 7. Что берём у сильных решений рынка

Речь идёт о паттернах, а не о копировании фирменного оформления других клубов.

| Референс | Сильное решение | Что берём |
|---|---|---|
| [Lakers.com redesign](https://infinum.com/work/los-angeles-lakers/) | игровые данные объединены с культурой и историями клуба; кейс сообщает рост вовлечения | после матча показываем людей, достижения и жизнь клуба, а не ленту одинаковых новостей |
| [Leicester Riders](https://riders.basketball/) и [кейс разработки](https://www.digitalplanning.tech/client-stories/leicester-riders/) | mobile-first, быстрый доступ к матчам, составам и контенту; раздельные мужская/женская команды | компактная навигация, match carousel и заметный Team Switcher |
| [Golden State Valkyries](https://valkyries.wnba.com/) | первый экран и начало ленты привязаны к ближайшей игре, затем идут видео/истории и следующий матч | ближайший матч — главный объект главной страницы; свежий результат идёт сразу следом |
| [Paris Basketball](https://parisbasketball.com/en/) | короткая верхняя навигация: fixtures, team, standings, news; сильный клубный слоган | не перегружаем header, правила и вторичные ссылки переносим в меню «Клуб»/footer |

Общий вывод рынка: спортивный сайт должен сначала отвечать «когда следующий матч, кто играет и как сыграли недавно», затем раскрывать состав и характер клуба. Магазин, билеты и новости нельзя имитировать пустыми разделами.

## 8. Готовая UI-основа

### Выбор: Nuxt UI

[Nuxt UI](https://ui.nuxt.com/) выбран основной системой, потому что предоставляет более 125 готовых Vue-компонентов, готовые responsive-шаблоны, семантические цветовые токены, тёмный режим и Figma Kit. Библиотека и шаблоны опубликованы под MIT.

Берём готовое:

- публичный shell — [Landing template](https://ui.nuxt.com/templates);
- базовые страницы и секции — `PageHero`, `PageSection`, `PageGrid`, `PageCard`;
- header — `Header`, `NavigationMenu`, `Slideover`;
- расписание — `Card`, `Carousel`, `Tabs`, `Badge`;
- фильтры — `SelectMenu`, `Input`, `Button`;
- таблица — `Table`, `Pagination`;
- состояния — `Skeleton`, `Alert`, `Empty`, `Toast`;
- диалоги — `Modal`, `Drawer`;
- будущая админка — готовый Dashboard template.

### Почему не смешиваем несколько UI-библиотек

[PrimeVue](https://primevue.org/) силён в DataTable, формах и FileUpload и остаётся запасным вариантом для отдельной тяжёлой админки. Однако смешивание PrimeVue и Nuxt UI в публичном интерфейсе создаст две системы токенов, размеров и поведения.

`shadcn-vue` и headless-наборы дают больше свободы, но требуют самостоятельно собирать почти каждый экран. Это противоречит текущему решению максимально использовать готовые компоненты.

Готовые HTML/WordPress sports themes не берём: они дублируют уже существующий backend, часто требуют другого runtime и усложняют типизированную интеграцию с API. Их можно использовать только как визуальные референсы.

## 9. Три дизайн-направления

### A. Game Night / Broadcast

Характер: эмоциональный, тёмный, похожий на экран спортивной трансляции.

- крупный ближайший матч в hero;
- огромные дата и счёт;
- красный главный CTA;
- тёмный фон, белые когти, диагональные переходы;
- горизонтальная лента последних результатов.

Плюсы: сразу чувствуется баскетбол и характер команды.

Риск: без хороших фотографий остальные страницы могут стать однообразными.

### B. Club Editorial

Характер: журнал о команде и игроках.

- чередование navy и светлых секций;
- крупные портреты и фамилии игроков;
- достижения как полноширинные истории;
- асимметричная, но спокойная сетка;
- когти используются как crop/разделитель, а не фон каждой карточки.

Плюсы: сильнее раскрывает людей и историю.

Риск: слабее показывает актуальное состояние сезона.

### C. Scoreboard / Data First

Характер: быстрый спортивный сервис.

- компактная полоса ближайшего матча;
- расписание, результаты и таблица доступны за один переход;
- минимум тяжёлых изображений;
- плотная, хорошо читаемая сетка.

Плюсы: лучший вариант для постоянных посетителей и мобильных устройств.

Риск: без брендового hero может выглядеть как универсальное спортивное приложение.

### Рекомендация: гибрид «Predatory Arena»

Использовать A для главной и страницы матчей, B для клуба/игроков, C для таблиц и мобильных сценариев. Все три режима строятся из одного Nuxt UI kit, одной палитры, одной типографики и одного набора когтей.

## 10. Структура главной страницы

```text
AppHeader
├─ эмблема + «Хищные Бобры»
├─ Главная / Команды / Матчи / Таблица / Клуб / Контакты
└─ mobile Slideover

Hero: ближайший матч
├─ соревнование и статус
├─ команды и логотипы
├─ дата, время, зал
├─ один CTA «Все матчи»
└─ крупные белые когти

Последние результаты
└─ готовый Carousel из 3–5 компактных score cards

Команды
├─ Tabs: Мужская / Женская
└─ состав + переход к игрокам

Турнирная таблица
└─ первые 5 строк + «Открыть таблицу»

Клуб и достижения
└─ светлая editorial-секция с одной сильной фотографией

Контакты / залы / соцсети
Партнёры
AppFooter
```

Главный CTA на стартовом экране — «Все матчи». Если появятся реальные билеты, он может быть заменён на «Купить билет» только для конкретного матча.

## 11. Шаблоны внутренних страниц

| Страница | Готовая композиция | Особенность бренда |
|---|---|---|
| Команда | `PageHeader + Tabs + PageGrid + Card` | крупная фотография команды, когти в заголовке |
| Игроки | responsive `PageGrid` | номер крупнее имени, лёгкий claw-overlay |
| Матчи | `Tabs + SelectMenu + Carousel/Card` | тёмные upcoming, светлые finished |
| Таблица | `Tabs + Table + Pagination` | sticky первые колонки, navy header |
| Клуб | `PageHero + PageSection + Carousel` | editorial-ритм и достижения |
| Правила | `PageBody`/Nuxt Content typography | светлая safe-zone, без декоративного шума |
| Контакты | `PageGrid + Card` | адрес всегда текстом, карта вторична |

Все data-страницы имеют готовые состояния loading, empty, error и retry. На мобильном таблица не превращается в картинку: ключевые колонки остаются видимыми, дополнительные доступны через раскрытие или обозначенный horizontal scroll.

## 12. Типографика, иконки и изображения

### Шрифты

- Заголовки: [Russo One](https://fonts.google.com/specimen/Russo+One) — спортивный характер и поддержка кириллицы.
- Интерфейс и длинный текст: [Manrope](https://fonts.google.com/specimen/Manrope) — спокойная читаемая кириллица.
- Счёт и статистика используют tabular numerals, но не требуют третьего шрифта.
- Название внутри официального логотипа не набирается заново.

Перед окончательным выбором в Figma проверяются слова «Хищные Бобры», длинные фамилии, названия соревнований и залов.

### Иконки

Используем готовый Lucide/Iconify-набор, входящий в экосистему Nuxt UI. Когти не используются вместо функциональных иконок.

### Фото

- единый crop портретов игроков;
- реальные командные фотографии вместо stock-фото;
- лица не перекрываются текстом и когтями;
- изображения получают фиксированные пропорции, WebP/AVIF и responsive variants;
- partner logo wall монохромный до hover, если это разрешено брендбуками партнёров.

## 13. Responsive и доступность

Проверяем макеты минимум на 390, 768, 1024 и 1440 px.

- mobile-first: ближайший матч и CTA помещаются без горизонтального скролла;
- drawer поддерживает клавиатуру, `Esc`, focus trap и возврат фокуса;
- видимый focus соответствует [WCAG 2.2 Focus Appearance](https://www.w3.org/WAI/WCAG22/Understanding/focus-appearance.html);
- интерактивные зоны ориентируются на размер не менее 44×44 px;
- hover никогда не является единственным способом увидеть данные;
- русский текст проверяется с запасом 50% длины;
- декоративные изображения скрыты от screen reader, содержательные имеют alt;
- score/status читается без зависимости от красного или зелёного цвета;
- режим reduced motion отключает параллакс, сдвиг когтей и масштабирование карточек.

## 14. Производительность

Остаются бюджеты из общего migration blueprint:

| Метрика | Цель |
|---|---:|
| initial JS public shell | не более 250 KiB gzip |
| CSS | не более 80 KiB gzip |
| стартовая страница | не более 2 MiB transfer |
| hero image | не более 500 KiB |
| LCP mobile 4G | менее 2,5 s |
| CLS | менее 0,1 |

Legacy-фон `fonbeavers.png` весит около 2,46 MiB, поэтому он служит master-референсом, а не готовым web-ассетом. Для сайта нужны responsive WebP/AVIF-варианты; когти желательно перевести в компактный SVG. Контрольные метрики сверяются с [Core Web Vitals](https://web.dev/articles/vitals).

## 15. План работ

### Этап 0. Утверждение направления

- утвердить гибрид «Predatory Arena» либо выбрать A/B/C;
- подтвердить палитру;
- получить master-логотип и актуальные фотографии;
- проверить права на эмблему ВГУ и партнёрские логотипы.

### Этап 1. Макеты без разработки

- дублировать официальный Nuxt UI Figma Kit;
- внести токены палитры и два шрифта;
- собрать из готовых блоков три варианта главной A/B/C;
- показать каждый вариант на 390 и 1440 px;
- использовать реальные русские подписи и данные матчей, не Lorem Ipsum;
- проверить когти, контраст и длину текста.

### Этап 2. UI-прототип

- собрать рекомендуемый гибрид в Figma;
- добавить внутренние шаблоны: команда, матчи, таблица, клуб;
- зафиксировать состояния loading/empty/error;
- согласовать фото, плотность и интенсивность когтей.

### Этап 3. Реализация публичного shell

- создать Nuxt-приложение из официального Landing template;
- подключить только брендовые токены и готовые Nuxt UI-компоненты;
- реализовать header, footer, routing и responsive shell;
- подключить типизированный клиент к существующему FastAPI OpenAPI.

### Этап 4. Реализация страниц

1. главная через `/api/v1/home`;
2. команды и игроки;
3. матчи и фильтры;
4. standings;
5. клуб, достижения, правила и контакты;
6. accessibility, visual regression, Lighthouse и E2E.

### Этап 5. Опционально позднее

- административная панель из Dashboard template;
- авторизация;
- новости, билеты, магазин и видео только после появления реальных требований и данных.

## 16. Definition of Ready для начала разработки

Разработку фронтенда начинаем, когда выполнено всё ниже:

- выбран один макет главной;
- утверждены цвета и шрифты;
- когти присутствуют на desktop и mobile без конфликта с контентом;
- получен пригодный логотип;
- есть хотя бы одна хорошая командная фотография и согласованный набор фото игроков;
- зафиксирована публичная навигация;
- все видимые блоки обеспечены существующим API или статическим контентом;
- в Figma используются компоненты, реально доступные в выбранном Nuxt UI template.

## 17. Итоговая рекомендация

Начинать не с пустого Vue/Vite-проекта и не со случайной sports theme, а с готовой связки:

```text
Nuxt + Nuxt UI
├─ официальный Landing template — публичный сайт
├─ официальный Figma Kit — макеты и токены
├─ существующий navy/red/white бренд
├─ существующий fonbeavers как основа фона
├─ обязательные когти как декоративный слой
└─ Dashboard template — только для будущей админки
```

Первая макетная итерация должна состоять из трёх готовых вариантов главной A/B/C. После выбора собирается гибрид «Predatory Arena»; только затем начинается код.
