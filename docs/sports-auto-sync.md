# Автоматическое обновление спортивных данных

На локальном компьютере обновление работает вместе с API. АСБ проверяется раз в час,
FIBA 3×3 — раз в сутки. Матчи, официальные таблицы, составы, статистика игроков и
официальные портреты АСБ обновляются независимо: недоступность одного источника
не останавливает остальные. Открытые страницы сайта проверяют обновления раз в минуту.

После календарей отдельно обновляются протоколы завершённых матчей текущего сезона
для мужской и женской команды (`asb_match_statistics_men/women`). Счёт по четвертям
доступен карточкам, а индивидуальные итоги и подтверждённые очки/броски по периодам —
Бобрику. При пустом ответе или потере ранее подтверждённых полей сохраняется последняя
хорошая версия; протокол с устаревшим счётом скрыт до согласованного обновления.
История загружается отдельно сборщиком из [asb-match-statistics.md](asb-match-statistics.md).

Статус: `/admin?tab=imports` → «Обновление данных». Для каждого источника видны
последняя успешная загрузка, следующая проверка и ошибка. Кнопка обновления статуса
только перечитывает статус. Дополнительные уведомления не отправляются.

## Локальный запуск

В `.env` настроены:

```dotenv
APP_RELOAD=false
APP_SPORTS_SYNC_ENABLED=true
APP_SPORTS_SYNC_INTERVAL_SECONDS=3600
APP_SPORTS_SYNC_FIBA_INTERVAL_SECONDS=86400
APP_SPORTS_SYNC_TIMEOUT_SECONDS=600
APP_SPORTS_SYNC_BACKEND_ROOT=.
APP_FIBA_API_KEY=
```

Запуск: `.venv/Scripts/python.exe run.py`. На Windows используется режим без reload,
поддерживающий фоновые дочерние процессы. Текущему пользователю Windows установлен
ярлык `Predatory Beavers Local API.lnk` в автозагрузку: он запускает
`scripts/start_local_background.ps1` при входе. Уже работающий API на порту 8000
повторно не запускается. Логи автозапуска: `data/api-autostart.*.log`.
Для отключения автозапуска удалите этот ярлык через `shell:startup`.

Проверки выполняются, пока компьютер включён и API работает. После сна или перезапуска
проверяются просроченные источники; круглосуточный сбор потребует постоянно работающего хоста.
После изменения `.env` API нужно перезапустить.

Ручной запуск учитывает то же расписание и блокировку:

```powershell
.venv/Scripts/python.exe scripts/refresh_sports.py --database data/local.db
.venv/Scripts/python.exe scripts/refresh_sports.py --database data/local.db --preview
```

`--preview` проверяет источники без импорта в БД и без изменения рабочих манифестов,
портретов или расписания. При первом запуске создаёт локальные копии исходных манифестов.

## FIBA

Без официального доступа сборщик показывает «Нужен доступ к API FIBA» и не делает
неавторизованных запросов. АСБ продолжает работать. Ключ задаётся только в серверном
`.env` (`APP_FIBA_API_KEY`), после чего API нужно перезапустить. Доступность и формат
выданного FIBA API необходимо подтвердить с FIBA: прежний Premium API закрыт.
[Официальная справка](https://help.fiba3x3.com/en/support/solutions/articles/35000118581)
направляет запросы на `3x3digital@fiba.basketball` с описанием проекта.

Отслеживаемые регистрации: `data/sports-sync/fiba-watchlist.json`, начальный шаблон —
`docs/fiba-watchlist.json`. Сейчас подтверждена мужская регистрация «Хищных Бобров»
на финале Росатома 2025 года. Новые турниры и женские регистрации требуют добавления
проверенных идентификаторов; известная регистрация не обнаруживает все будущие события.
Подробности формата и адаптера: [fiba-sync.md](fiba-sync.md).

## Сохранность данных

Повторный импорт не дублирует матчи. Подтверждённые исправления источника обновляют
его прежние значения; редакторские изменения и удаления сохраняются. Некорректный
или неполный ответ источника оставляет последние проверенные данные.

Рабочие манифесты, статус и кеш портретов находятся в `data/sports-sync/` и не изменяют
файлы в `docs/` или исходный снимок `data/predatory_beavers.db`. Перед первым обновлением
за день создаётся согласованная SQLite-копия в `data/backups/sports-sync/`; сохраняются
последние семь дневных копий. Параллельные запуски защищены блокировкой на уровне ОС.
