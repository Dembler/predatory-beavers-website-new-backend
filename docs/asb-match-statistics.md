# Официальная статистика матчей АСБ

На сайте календарные и архивные карточки показывают компактный счёт четвертей и
овертаймов из `score_by_periods` в списках матчей и результатов. Очки каждого периода
показаны отдельно, с явным порядком команд; пустой список не заменяется нулями.
Полные протоколы и таблицы игроков в интерфейсе карточек не выводятся.

Подробная спортивная проекция остаётся доступна Бобрику и через
`GET /api/v1/game-statistics/asb/{GameID}` в оболочке `{message,data}`. Календарь и
архив связываются по паре `source/external_id`, а не UUID друг друга. `data:null`
означает, что для публичного матча нет подтверждённого актуального протокола;
неизвестный или скрытый родитель возвращает 404.

Первичные публичные источники проверены реальными GET 17 ноября 2026 года:

- [Матч мужчин 1138965](https://asb.sportoteka.org/api/abc/games/game?id=1138965&tag=asb&season=2027&lang=ru).
- [Матч девушек 1138973](https://asb.sportoteka.org/api/abc/games/game?id=1138973&tag=asb&season=2027&lang=ru).
- [Официальный словарь событий](https://asb.sportoteka.org/api/basket/stats/plays?onlyBase=false).
- [Предыдущий виджет GameBoxScore](https://asb.infobasket.su/Widget/GameBoxScore/1138965?format=json)
  даёт итоги, но поле ScoreByPeriods у проверенного матча пустое. Оно не заменяется догадкой.

В Sportoteka `game.fullScore` содержит очки **за каждый период**, а не накопленный счёт.
В игре 1138965 это 19:12, 12:11, 17:16, 12:12; сумма даёт 60:51. У Юрия Провоторова
19 очков, по четвертям 7, 2, 6, 4. В игре 1138973 счёт четвертей 11:23, 3:23, 4:24,
7:20; итог 25:90. У Дарьи Кузнецовой 7 очков, по четвертям 4, 0, 2, 1.

В таблице `match_statistics` хранится только нормализованная спортивная проекция:
итог, четверти и ОТ, обе команды и индивидуальные итоги. Из неё карточки получают
только компактные счета периодов, а Бобрик — подтверждённые подробности.
Домашняя сторона всегда соответствует официальной team1, гостевая — team2.
`club_side` вычисляется по подтверждённому ASB team ID (7433/7695), а не по залу
или тому, как архивная карточка рисует команду клуба.

Очки и броски игроков по четвертям восстанавливаются из событий Goal1/2/3 и Miss1/2/3
только после сверки всех игроков с итогами протокола и всех периодов с командным счётом.
Поэтому `player_periods_status=partial`: подборы, передачи, минуты, перехваты и другие
показатели за четверть остаются `null`. Итоги за матч никогда не подставляются вместо
поквартальных значений. Технические результаты и незавершённые матчи не получают
выдуманных четвертей. Отсутствующие показатели — `null`, подтверждённые нулевые — 0.
Поле `played` отличает участие, подтверждённый DNP и неизвестное участие.

Снимок сбора от **17 ноября 2026, 20:06:24 UTC** охватывает 150 проверенных ID из
сохранённого архива АСБ. Нормализованы 122 протокола: 71 мужской и 51 женский,
сезоны 2020–2021 — 2026–2027. Покрытие разных полей не совпадает:

| Данные | Матчей из 150 |
| --- | ---: |
| Принятый нормализованный протокол | 122 |
| Подтверждённые счета периодов | 102 |
| Индивидуальные итоги игроков за матч | 121 |
| Очки и броски игроков по периодам | 101 |
| Отклонены проверками согласованности | 22 |
| Недоступны у источника | 6 |

Числа полей пересекаются и не суммируются. У 101 принятого протокола периодная
статистика игроков частичная; у остальных 21 она недоступна. Это покрытие конкретного
снимка, а не обещание наличия данных у каждого исторического матча. Отклонённые
22 ответа не импортируются как достоверные протоколы. Воспроизводимые локальные
артефакты: `.data/asb-match-statistics-all.json` и
`.data/asb-match-statistics-all-report.json`.

API и поиск Бобрика используют общий `public_statistics(session)` с проверкой текущего
родителя. Скрытый матч не раскрывается через архивную копию; изменение счёта, стороны,
команды, сезона или статуса сразу скрывает старую версию протокола. GET одного матча
фильтрует SQL до загрузки JSON и не читает весь архив протоколов. В публичном ответе
нет дат рождения, контактов, ростовых данных или сырых профилей источника.

Бобрик различает итог матча, командные очки периода, индивидуальный итог и сезонное
среднее. Для «последнего матча» сначала выбирается опубликованный завершённый матч
нужной команды; отсутствие его протокола не подменяется подробностями более старой
встречи. Если мужская и женская команды не различимы, требуется уточнение.
Игроки однофамильцы сохраняют отдельные официальные ID и сторону команды.
Сравнения по очкам, подборам, передачам и времени используют всю подходящую группу,
сохраняют разделённое лидерство и отделяют DNP от неизвестного показателя.
Сезонная статистика заявки маркируется своим `statistics_season`: текущая заявка
с прошлогодними средними не становится полным историческим составом.

Сбор и импорт разделены: сеть вызывается перед транзакцией. Сборщик
`scripts/collect_asb_match_statistics.py` берёт проверенные ID из `docs/results-asb.json`.
По умолчанию это последний сезон; `--all` включает историю. Без `--apply` запись
в БД не выполняется. Для изолированной локальной базы:

```powershell
.venv/Scripts/python.exe scripts/collect_asb_match_statistics.py --all --output .data/asb-match-statistics-all.json
.venv/Scripts/python.exe scripts/collect_asb_match_statistics.py --input .data/asb-match-statistics-all.json --database data/bobrik-local.db
.venv/Scripts/python.exe scripts/bobrik_local.py init
.venv/Scripts/python.exe scripts/collect_asb_match_statistics.py --input .data/asb-match-statistics-all.json --database data/bobrik-local.db --apply
```

Миграция 0024 добавляет новую таблицу, не меняя редакторские поля матча.
Неполный ответ источника не удаляет последнюю хорошую версию; старые и новые поля разных
версий протокола не смешиваются. Недоступность и отклонённые протоколы видны в coverage
отчёта, поэтому наличие подробностей не обещается для каждого исторического матча.

Изолированные тесты используют две урезанные реальные фикстуры из указанных источников,
без личных профильных полей, и искусственные повреждения: перепутанные стороны,
накопленные счёты, неверные суммы, ОТ, DNP, дубликаты событий, отсутствующие броски,
смену публичности и исправления счёта. Обычная `data/predatory_beavers.db` при этих
проверках не используется.
